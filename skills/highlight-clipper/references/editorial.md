# 编辑标准：充分发现，忠实切取

## 目标和优先级

发现全片中值得独立观看、分享或讨论的内容，然后帮助用户选择制作顺序。优先级只用于安排观看，备选仍保留在候选库和交付中。不要先决定“选 5 条”，再拿条数当作完成标准。

精彩没有唯一答案。采用多个发现入口，任何一种观看价值突出即可入选，不要求同时满足所有条件，也不以固定总分自动淘汰。

| 发现入口 | 回读时可以关注什么 |
| --- | --- |
| 具体案例与故事 | 出人意料的做法、反常细节、亲历场景、前后变化、故事转折 |
| 解释与洞见 | 熟悉问题的新解释、清楚的因果链、复杂事物的简单表达 |
| 观点与冲突 | 尖锐立场、价值冲突、反直觉判断、反问与交锋 |
| 生活关联 | 工作、家庭、教育、金钱、身份或选择中的具体困境 |
| 方法与提问 | 可尝试的行动、值得反复问自己的问题、简明方法 |
| 语言与情感 | 金句、形象比喻、幽默、情绪积累、振奋、共鸣 |
| 现场互动 | 追问、接话、反应、停顿、笑声、从玩笑到认真回答的变化 |

这些是发现线索，不是标签配额。没有每一类候选完全正常；没有单句金句的完整故事仍可能非常精彩。

## 判断内容，不裁决发言真伪

**不得因外部真实性、数据准确性、信源充分性或可信度而排除、降级片中亮点。** 强断言、夸张、缺少依据、误解和自相矛盾，也可能构成观看价值。

同时，切片必须忠实于原片：

- 转写写错了金额、单位、名称或否定词，要回到原片确认；不能直接把外部资料中的“正确答案”改写成说话人的原话。
- 保留观点的适用条件、承认未知、引用归属，以及玩笑后改变含义的澄清。
- 标题与理由使用“他说”“他认为”“旁白主张”等恰当归属，不把片中断言写成本工具已核实的事实。
- 采访者的质疑与嘉宾的回答都按原样理解，不擅自断言某人“已经驳倒”另一人。
- 用户另行要求事实核查时，另列核查结果，并保留原候选和原始表达。

## 全片发现的具体做法

先通读全文，建立按顺序覆盖全部字幕的主题表，再分别做三次回读：故事与案例、观点与冲突、语言与互动。每次都需要回到对应原文，而非只从上一次的摘要中挑选。

长视频可以分批阅读，但每批保留主题和原文定位，并在结尾做全片复查。不要让早期摘要丢掉细节后，再要求后续模型“尽量不漏”。

合并三遍候选后，检查：

1. 未出现候选的主题是否还有具体例子、类比、情感或互动价值？
2. 是否只选了最容易拟标题的论断，而漏掉解释、故事和微妙回应？
3. 是否因已有同主题片段，漏掉另一种表达、另一个角色或另一个例子？
4. 是否因长度超过习惯值、没有单句金句而排除了好内容？
5. 是否把备选藏起来，或用不确定性替用户提前作了取舍？

在 `passes.omission_review` 和各主题的 `audit_note` 记录有内容的回查说明。不要仅填写“已检查”“无遗漏”来满足字段。

## 上下文取多长

从核心亮点向前后寻找完整的意义单元。不要统一加减 10 秒，也不要一律从回答开始或一律带上所有问题。

向前检查：

- “这件事”“他们”“所以”具体指什么？
- 观点是在回应哪个问题、质疑或生活处境？
- 核心句的冲击力是否依赖前面的故事铺垫？
- 是否需要保留追问，观众才看得出回答是在正面回应、转移角度或开玩笑？

向后检查：

- 后面是否还有必要的理由、例子或完整收束？
- 有没有改变含义的条件、补充、承认未知或玩笑澄清？
- 现场笑声、对方反应是否属于亮点的一部分？
- 是否不小心带走下一话题的开头，留下悬空连接词？

有两种长度都合理时，保留“核心版”和“完整语境版”，说明长版增加了什么，让用户比较。`variant_of` 指向同组主版，`context_note` 说明差异。主版不是越长越好，也不是越短越好。

## 访谈和多来源视频

提问、插话、追问与回答要分别理解。一个问题可能有多个子问题，回答也可能隔一段才补充。通过 `question_ids` 记录相关句子编号，并在 `context_note` 写清未包含在片段内的关联。

自动说话人编号不等于人物身份，也不等于配音声线。发现“同一人自问自答”、语气明显转换、观众提问被标为嘉宾等异常时，回读对话和查看相应画面。镜头中的人物也可能只是反应镜头，单张画面不足以证明谁说了整段话。

包含原访谈、上传者旁白和预告的视频，先分清来源层，再选择内容。评论旁白可以很精彩，但不能归为受访者原话；重复转述同一观点也不是多个独立事实来源。来源不明就明确标注，不能靠猜测补齐。

每条候选都切自一个连续的原片时间区间。跨时段补答可以作为关联候选，不能无提示拼接为连续原声。制作集锦时仍要保留原片位置和剪辑关系。

## 重复和变体

区分以下三类：

- **同主题，不同价值**：一个故事和一个比喻可以同时保留。
- **同一内容，不同长度**：长短版本关联保存，供上下文比较。
- **实际重复**：开场预告复用了正文，或一个短片完整包含在另一个长片中。说明关系，避免集锦重复播放。

程序能计算时间区间重叠，但不能仅靠时间发现“预告在另一个时段复用了正文”。这种重复需要编辑回读和说明。

## 反馈与效果判断

用户反馈使用四个标签：**必选、可选、不选、选点对但范围不对**，并可附一句原因。把“喜欢这个点”和“喜欢这次切取范围”分别理解。

反馈针对实际观看的片段版本。修改范围或转写后保留旧意见作为历史，不把它自动当成用户对新版本的评分。多个入口留下不同意见时先保全并复核，不擅自选择其中一个覆盖另一个。

对于没有看过原片的用户，先提供简短内容导览及较短的首次观看入口。可以先只展示片段标题、来源和视频，让用户形成观感，再看详细编辑理由。

质量可从已知喜欢的片段是否被找到、额外发现的好片段、上下文满意度和审阅耗时来比较。有限参考清单的覆盖率不等于全片真实召回率；文件检查通过不等于听审通过；几次选片获认可也不等于已经验证传播效果。
